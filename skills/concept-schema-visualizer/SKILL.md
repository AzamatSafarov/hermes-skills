# Concept Schema Visualizer Skill

Переводи сложные теоретические, академические, юридические и методологические тексты в простые, но содержательные схемы на основе визуального глоссария (объект, место, позиция, условие, событие, процесс, действие, связь, контекст, ограничение, время, фокус и т.д.). Схема не украшает текст — она показывает его структуру.

Скилл работает в два такта: сначала семантический разбор текста, затем рендер через движок `render_schema.py`, который превращает JSON-спеку в HTML/SVG. Не рисуй SVG руками — всегда используй движок.

## When to Use

Используй этот скилл, когда пользователь просит:
- «засхематизировать» статью, абзац, аргумент, концепцию или спор;
- сделать визуальную карту онтологических, методологических, юридических или политических позиций;
- показать взаимодействие акторов, действий, последствий, ограничений и контекста;
- превратить сложный текст в схему для понимания, объяснения или презентации.

Не используй для фотореалистичных иллюстраций, инфографик со статистикой, архитектуры ПО (там лучше `architecture-diagram`), или когда нужен полностью редактируемый файл без структуры спеки (тогда чистый `excalidraw`).

## The Engine

**Расположение:** `scripts/render_schema.py` внутри папки скилла (после установки — `~/.hermes/skills/concept-schema-visualizer/scripts/render_schema.py`).

Строго stdlib (json, html, math, argparse). Никаких внешних зависимостей. Схема определяется JSON-спекой; движок сам считает размеры узлов, слои, рамки, кривые рёбер, подписи чипов и легенду.

### Запуск

```bash
python scripts/render_schema.py spec.json -o schema.html
```

Ключи:
- `--page` — автономная страница с фоном (для брошюры/печатного вида);
- `--canvas out.canvas` — экспорт в Obsidian Canvas (вложенные текстовые карточки + стрелки);
- `--excalidraw out.excalidraw` — экспорт в Excalidraw (прямоугольники/эллипсы/ромбы + стрелки);
- `--strict` — предупреждения дают код возврата 1 (для контроля качества).

Движок сам печатает WARN/ERROR по спеке:
- узел без id, повтор id, неизвестная графема/тип связи/рамки;
- причинные связи (`action`/`control`/`shift`) без поля `basis` — главный механизм против выдумывания причинности;
- >15 узлов в схеме — сигнал дробить на пакет;
- ссылки рёбер на несуществующие узлы — ошибка;
- значения вне диапазона на картах.

**Правило grounding:** каждая причинная стрелка обязана опираться на текст. Поле `basis` — короткая ссылка на источник («разд. 2», «как показано в [X, с. 45]», «прямая цитата автора»). Движок предупредит, если поля нет; в сомнительных случаях используй `tension` или `link` вместо `action`.

## Interpretation Modes

Работай в двух режимах.

### 1. Explicit Brief Mode
Пользователь прямо задал, что визуализировать — следуй заданию, но проверь, не требует ли текст дополнительного слоя (контекст, ограничения, время, карта позиций).

### 2. Autonomous Semantic Mode
Дан длинный текст без точного задания. Не визуализируй по порядку абзацев. Сначала определи, что текст делает:
- классифицирует подходы;
- сравнивает позиции;
- строит аргумент против альтернатив;
- описывает процесс;
- реконструирует историческую динамику;
- вводит новую модель;
- показывает ограничения существующих объяснений;
- сводит несколько онтологий к мета-рамке.

Критерий завершения: перед рисованием есть ясный ответ на вопрос «какая интеллектуальная операция выполняется в тексте?»

## Macro-Structure Detection

Для статей и больших фрагментов сначала выдели макроструктуру:

1. **Главный предмет** — о чем статья на верхнем уровне.
2. **Центральный тезис** — что автор доказывает, уточняет или реконструирует.
3. **Набор подходов / онтологий / режимов** — сколько их и чем различаются.
4. **Критерий сравнения** — субъект, объект, действие, причинность, норма, контекст, практика, уровень анализа.
5. **Интегрирующая рамка** — есть ли модель, которая собирает остальные подходы.
6. **Тип отношений между подходами** — конкуренция, вложенность, историческая смена, дополнение, конфликт, редукция, синтез.
7. **Ограничения и слепые зоны** — что каждый подход не видит.

Если подходов 3+, не делай одну перегруженную схему. Делай пакет:
- мини-схема для каждого подхода;
- сравнительная матрица (`matrix` в спеке);
- обзорная интеграционная схема, показывающая, как подходы входят в общую рамку.

## Multi-Schema Planning

| Ситуация в тексте | Что делать |
|---|---|
| Один аргумент или процесс | 1 схема |
| 2–3 позиции | 1 сравнительная карта + при необходимости 1 итоговая схема |
| 4+ подходов | N мини-схем + 1 синтетическая схема |
| 5 подходов сравниваются с шестым | 5 схем подходов + 1 схема шестой рамки + 1 обзорная «как пять входят в шестую» |
| Текст содержит историю и теорию | 1 временная схема + 1 концептуальная схема |
| Норма, практика и последствия | 1 процессуальная схема + 1 рамка ограничений/контекста |

Критерий завершения: количество схем соответствует структуре текста.

## Visual Glossary

| Текстовая функция | Графема | Форма | Когда применять |
|---|---|---|---|
| Сущность, понятие, тезис | `object` | прямоугольник | Понятия, вещи, документы, нормы, подходы |
| Среда, поле, состояние | `place` | овал | Где действует объект или разворачивается практика |
| Агент, участник, точка зрения | `position` | фигурка | Автор, институт, субъект действия |
| Логическая развилка | `condition` | ромб | «если/то», критерий, проверка |
| Значимый факт | `event` | щиток | Инцидент, решение, переломный момент |
| Процедура, механизм | `process` | широкая стрелка | Административная процедура, метод, цикл |
| Уровень анализа | `plane` | параллелограмм | Онтологический, эпистемический, нормативный слой |
| Смысловой центр | `focus` | точка + текст | Главный тезис, ядро |
| Термин, условное имя | `term` | плашка-метка | Обозначение понятия, символа |
| Действие, влияние | `action` | стрелка | «ведет к», «порождает», «меняет» |
| Нейтральное отношение | `link` | линия с точками | Связь без направления |
| Управление, регулирование | `control` | стрелка с засечкой | Норма, команда, институциональный контроль |
| Сдвиг фокуса | `shift` | стрелка с риской | Смещение проблемы, перенос акцента |
| Спорность, конфликт | `tension` | пунктир | Напряжение, несводимость позиций |
| Контекст | `context` (рамка) | L-рамка | Фон, среда обсуждения |
| Ограничение | `constraint` (рамка) | П-рамка | Предел применимости, запрет |
| Группа | `group` (рамка) | пунктирная рамка | Объединение элементов |
| Граница | `boundary` (рамка) | линия | Внутри/снаружи, до/после |

Эпистемические модификаторы узлов (передаются через `epistemic`):
- `source` — прямая фиксация текста;
- `reconstruction` — реконструкция смысла из текста;
- `interpretation` — интерпретация PNS, не буквальное прочтение (пунктирный контур);
- `norm` — нормативное утверждение (утолщённый контур).

Модификаторы: `emphasis: true` (ключевой узел, плотная заливка), `marker: "star"` / `"hash"` (особый статус), `badge: "A"` для `term`.

## Spec Reference

Полная JSON-спека (подробности в docstring движка; рабочие примеры в `examples/`):

```json
{
  "title": "…", "subtitle": "…", "footer": "…",
  "matrix": {"columns": ["…"], "rows": [{"label": "…", "cells": ["…"]}]},
  "schemas": [
    {
      "kind": "graph",
      "title": "…", "note": "…",
      "nodes": [
        {"id": "a1", "grapheme": "object", "label": "Понятие", "note": "пояснение",
         "layer": 0, "slot": 0, "emphasis": false, "epistemic": "source", "marker": null}
      ],
      "edges": [
        {"from": "a1", "to": "a2", "type": "action", "label": "порождает", "basis": "разд. 2"}
      ],
      "frames": [
        {"id": "f1", "kind": "context", "label": "Контекст: …", "members": ["a1", "a2"]}
      ]
    },
    {"kind": "map", "title": "…", "xLabel": "агентность →", "yLabel": "структурность →",
     "items": [{"label": "Позиция", "x": 0.8, "y": -0.6, "emphasis": false}]},
    {"kind": "timeline", "title": "…",
     "points": [{"label": "Событие", "t": 0.5}]}
  ]
}
```

Правила спеки:
- `layer` — номер колонки слева направо; если не задан, выводится из стрелок; явные значения жёсткие.
- `slot` — порядок внутри колонки (меньше = выше); по умолчанию порядок объявления.
- `id` уникальны в пределах схемы; рёбра могут ссылаться на рамки.
- У одной пары узлов может быть несколько рёбер — движок разведёт их дугами.
- Обратные и «плохие» рёбра (через колонку назад или большой вертикальный перепад) рисуются дугой над/под схемой.
- `matrix` — сравнительная таблица подходов; рендерится под схемами.
- Карта: `x`/`y` в диапазоне [-1, 1] относительно центра; подписи слева/справа от точки.
- Таймлайн: `t` — относительное положение (обычно 0…1).
- Заголовок схемы = 5–15 слов, `note` = 1–2 предложения интерпретации.

## Procedure

1. **Определи задание или реконструируй его.** Explicit Brief или Autonomous Semantic Mode.
2. **Разбери текст.** Макроструктура → список узлов/связей/рамок; для статьи — тезис, подходы, критерий сравнения, интегрирующая рамка, ограничения.
3. **Выбери пакет схем** по Multi-Schema Planning.
4. **Составь JSON-спеку.** Графемы из глоссария; причинным связям — `basis`; конфликтность — `tension`; эпистемические уровни — через `epistemic`.
5. **Сохрани спеку** через `write_file` рядом с рендером (например, `schema-spec.json`).
6. **Запусти движок** через `terminal`:
   ```bash
   python scripts/render_schema.py spec.json -o schema.html
   ```
   Читай WARN/ERROR. Исправляй спеку, пока ERROR не исчезнут, а WARN по grounding не будут обоснованы.
7. **Проверь схему против текста.** Каждая стрелка обоснована текстом; нормативное не выдано за факт; конфликтующие позиции не сглажены.
8. **Покажи результат.** В чате Hermes — `::preview{file="<путь>/schema.html"}` отдельной строкой. Для Obsidian — `--canvas`, для ручного редактирования — `--excalidraw`, выдавай через `MEDIA:/…`.

## Pitfalls

- Не рисуй SVG руками — только спека + движок. Ручные координаты ломают layout и легенду.
- Стрелка означает направленность/влияние/переход; не добавляй их ради динамики. Для сопоставления — `link`, для спора — `tension`.
- >15 узлов в схеме — дроби на пакет. Движок предупредит.
- Поля `basis` без текста = выдуманная причинность. Движок предупредит; в спеках для статей всегда заполняй.
- `condition` и `event` визуально широкие; планируй `layer` так, чтобы развилки не съедали ширину.
- Canvas-экспорт не переносит рамки; Excalidraw приближает position/process/event/plane/term прямоугольниками — предупреждение будет в выводе.
- Obsidian-файлы не класть в vault для review-артефактов: HTML-схемы храни в отдельной папке для review или рядом со статьёй, markdown-статьи — в vault.

## Verification

Перед ответом пользователю:

- [ ] Спека сохранена отдельным файлом (`write_file`), движок запущен через `terminal`.
- [ ] Движок вернул `OK`, ERROR нет; WARN разобраны (особенно grounding/basis).
- [ ] Все 23+ SVG валидны (движок не роняет XML) — при ручной проверке: 0 out-of-bounds текстов.
- [ ] Каждая причинная стрелка имеет `basis` или заменена на `link`/`tension`.
- [ ] Главные элементы текста представлены; конфликтующие позиции не сглажены.
- [ ] Контекст/ограничения визуально отделены рамками.
- [ ] Есть заголовок, note-интерпретация и легенда (легенду генерирует движок автоматически).
- [ ] Ответ содержит `::preview{file="..."}` или `MEDIA:/...` артефакт.
- [ ] Все файлы сгенерированы заново движком, а не сохранены из головы.
